# Deck Session UI

## Context
Build a separate nearby-printer game UI that accepts 2–4 Commander deck links, imports each deck, and lets players operate the decks as physical objects. A browser-only session must preserve the full 100-card instance state for each deck, including randomized library order and cards moved to other zones, so simulated actions remain deterministic without pretending to know the physical order. The UI must show session/deck/card metadata and the print path must place a compact identifier on printed proxies.

## Approach
1. Add a deck-import boundary that accepts links from the major supported deck providers and returns one normalized Commander deck.
   - Create `src/lib/server/decks.ts` with a provider adapter registry. Each adapter recognizes only its provider host/path, fetches the provider's public deck/export representation server-side, parses card names and quantities plus commander designation, and resolves names through the existing Scryfall normalization path. Include adapters for Moxfield, Archidekt, TappedOut, Deckstats, and Scryfall deck/list links; support provider export/list endpoints rather than scraping rendered HTML when the provider exposes one. If a provider has no usable public representation, return the existing API error shape with an explicit unsupported/unreadable-link message instead of fetching arbitrary URLs.
   - Normalize every imported deck to exactly 100 card instances including the commander. Reject missing commander metadata, invalid quantities, unresolved cards, and totals other than 100 with HTTP 400. Keep commander instances identified in metadata but initially place them in the command zone; the other 99 instances form the library.
   - Use immutable normalized fields already available from `CardRecord` (`id`, `name`, set/collector data, image and preview URLs) and add only deck-specific fields needed by the session: `deckId`, `deckName`, `cardNumber` (1–100), `isCommander`. Preserve duplicate cards as separate instances, not a count-only record.
   - Add `src/routes/api/decks/+server.ts` with `POST` validation for `{ links: string[] }`, requiring 2–4 non-empty strings, and return normalized decks. Validate URL protocol and provider allowlist before any server fetch to avoid an SSRF path. Preserve the cards and deck labels needed by the browser; never expose provider credentials or printer settings.

2. Add the separate game route and browser session model.
   - Create `src/routes/play/+page.svelte`; leave the existing printer page and its queue behavior unchanged. Because the current global theme tokens, body reset, form styles, and focus styles live only in `src/routes/+page.svelte`, first extract those exact `:global()` rules into a new `src/routes/+layout.svelte` so both routes share the existing light/dark behavior without visual drift. The route has an import/start screen for 2–4 links and a game screen after successful import. Reuse `ThemePicker` and `ErrorToast` conventions, but give the play surface a dense, high-contrast tabletop layout designed for standing players: one deck panel per player, large controls, clear zone counts, visible focus states, and no interaction that depends only on hover.
   - Keep state in `localStorage` under a versioned key such as `mtg-play-session-v1`; do not add a database or server session. Generate a session ID with `crypto.randomUUID()` once per new game and display a short readable prefix while retaining the full ID in stored state. Load only valid versioned state; on malformed/stale state, discard it and show the start screen rather than partially restoring it.
   - Define the client model with immutable card instances `{ instanceId, scryfallId, name, imageUrl, deckId, deckName, cardNumber, isCommander }`, per-deck zones `{ library: string[], hand: string[], graveyard: string[], exile: string[], command: string[] }`, and a session event/history or action log sufficient to show the last action. Store card instances separately from zone ID arrays so every physical card remains traceable.
   - On start, create one `instanceId` per copy (including duplicates), put the 99 non-commanders in `library`, put the commander in `command`, shuffle each library with an unbiased in-place Fisher–Yates implementation using a production `crypto.getRandomValues` source, then persist. Expose the shuffle helper as `shuffleIds(ids: string[], randomUint32: () => number)` so state tests can supply deterministic values without replacing production randomness. On refresh, restore exactly the saved arrays; never reshuffle automatically. If the browser lacks `crypto.getRandomValues`, block session start with an explicit error rather than using a weak fallback.

3. Implement the physical-deck actions and transitions.
   - Provide buttons and keyboard-accessible controls for each deck: `Draw opening hand` (draw 7), `Mulligan` (return the current opening hand to that deck's library, shuffle, draw one fewer card, and allow repeated mulligans), `Keep hand`, `Draw card`, `Mill` (move the top library card to graveyard, with a disabled state when empty), `Exile top`, `Reveal library top`, `Shuffle library`, `Move hand card to graveyard`, `Move hand card to exile`, and `Return card to library` from graveyard/exile. A kept hand cannot be mulliganed; reset the current game is an explicit confirmation action that creates a new session ID and randomizes fresh libraries.
   - Centralize all transitions in one pure client module `src/lib/game-state.ts`; each action must validate source availability, move the exact `instanceId`, update counts, persist the resulting state, and append a plain-language action entry. Do not duplicate zone mutation logic in Svelte components. Empty-library draws/mills are no-ops with a visible status message; invalid card IDs or unknown zones are rejected without changing state.
   - Show private hand cards only in the owning deck panel, show face-down library counts, and show graveyard/exile contents with card name, card number, source deck, and zone. The session header shows the short session ID and each deck panel shows its stable deck label and card number metadata. Use the existing `CardPreview`/Scryfall image conventions where useful; add no new dependency.
   - Add a per-deck `Search library` control that filters that deck's remaining library instances by card name, shows matching card metadata, and lets the player select exactly one instance to move to hand; after any selection, shuffle the remaining library and record the search action. Searching an empty library or selecting an unavailable instance is a visible no-op. Add a `Basic land` shortcut row for Plains, Island, Swamp, Mountain, Forest, and Wastes; each shortcut finds one matching instance in that deck's library, moves it to hand, shuffles the remainder, and disables/reports when that land is not present. These are state-machine actions, not fabricated cards, so the deck remains a closed 100-instance set.

4. Add game-specific printing with visible card metadata.
   - Add `src/routes/api/game-print/+server.ts` accepting `{ sessionId, cards: [{ id: string, label: { deckId: string, cardNumber: number, deckName: string } }] }`. Validate UUID/card IDs, card-number range, non-empty deck labels, and a bounded batch size; resolve card images server-side with `getCard`; never trust client-supplied card names or image URLs. Reuse `enqueuePrint` so physical writes remain serialized.
   - Extend the rendering path with an optional metadata argument, keeping `renderCard(imageBytes)` output and dimensions unchanged when omitted. For game printing, composite a small high-contrast footer over the bottom of the existing 512×712 grayscale image containing the short session ID, deck label, and `cardNumber/100`; use escaped SVG text and fixed dimensions so labels cannot inject markup or change output size. The play UI prints selected/visible cards through the new route and reports success/failure using the existing error/status pattern. The old `/api/print` contract remains unchanged for the original printer page.

5. Add behavior coverage for the state machine, import boundary, and metadata render path.
   - Create focused tests alongside the new server/client modules. Assert Fisher–Yates output is a permutation and deterministic injected randomness does not duplicate or lose instances; assert opening draw, repeated mulligan, draw, mill, exile, graveyard return, search-to-hand, basic-land shortcut, and empty-library behavior preserve the zone/card invariants and persistable shape; assert malformed deck totals and unsupported/untrusted links return 400 without upstream fetching; assert metadata rendering still produces exactly `512 × 712` output and visibly changes only when metadata is supplied.

## Critical files & anchors
- `src/routes/+page.svelte` — existing printer page; preserve its current queue/import/print contract while adding the separate route.
- `src/lib/server/scryfall.ts` — `CardRecord`, `resolveCardNames`, and `getCard`; reuse normalized card data instead of creating a second Scryfall model.
- `src/lib/server/render-card.ts` — `renderCard` and the fixed `CARD_WIDTH`/`CARD_HEIGHT`; optional metadata must preserve the current no-metadata output dimensions.
- `src/lib/server/printer.ts` — `enqueuePrint`/`printCard`; retain serialized socket writes and extend only the render-input path required by game printing.
- `src/routes/api/` — existing explicit Zod/API error conventions; add deck import and game-print routes without weakening the current trust boundary.

## Assumptions & contingencies
- “Commander deck” means exactly 100 cards total, with exactly one provider-designated commander represented separately in the command zone and the remaining 99 in the library. If a provider marks multiple commanders or none, reject the import rather than inventing commander selection.
- “Any major provider” is implemented as the five explicit adapters named above plus a provider registry so adding another provider is localized; links outside those adapters fail clearly instead of using arbitrary remote fetches. If a provider changes or blocks its public export during implementation, keep its adapter error explicit and use that provider’s documented public export format rather than scraping authenticated/private pages.
- Browser-only persistence means another device cannot join and clearing site storage ends the session. The full session ID is metadata only; it is not a server lookup key.
- Physical metadata is a footer overlay on the grayscale proxy, not a separate label printer or a change to the existing default print output. If a printer cannot reproduce the footer legibly at its calibrated size, retain the UI metadata and surface the print failure; do not silently omit identifiers.
